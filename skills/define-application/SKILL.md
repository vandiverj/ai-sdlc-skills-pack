# define-application

## Description
Define the whole application before defining features or implementation tasks.

## Purpose
Create enough shared context for grilling, modeling, PRD creation, and issue planning.

## Do not
- Create a full PRD
- Break work into issues
- Write code
- Choose detailed architecture too early

## Required sections
- Application name
- One-sentence description
- Target users
- Problem statement
- Core workflows
- Major feature areas
- Core data concepts
- External integrations
- MVP boundary
- NOT in scope
- What already exists
- Open questions
- Recommended next use of `grill-me`

## Approval behavior
For meaningful applications, present the definition in sections and ask for approval or revision before proceeding to modeling.
