# Technical Approach

Use when implementation changes architecture, stack, dependencies, persistence, deployment, runtime behavior, external integrations, or operational constraints.

## Checks
- Approach fits the existing codebase and project constraints.
- New dependencies are justified and approved.
- Data, migration, rollback, security, performance, and operability impacts are understood.
- Simpler local patterns were considered before adding abstraction.
- Verification and release implications are explicit.

## Output
- Recommended approach.
- Alternatives considered.
- Tradeoffs.
- Approval gates.
- Verification and rollback expectations.
