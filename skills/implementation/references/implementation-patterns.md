# Implementation Patterns

Use when a task touches repeated project structures such as forms, tables, API handlers, data fetching, errors, tests, page layouts, or feature modules.

## Checks
- Existing project pattern docs and canonical examples are inspected.
- Standard or Validated patterns are followed when applicable.
- Emerging or Experimental patterns stay bounded.
- Deprecated or Superseded patterns are not copied.
- Deviations are tied to requirements, framework constraints, accessibility, security, performance, or maintainability.

## Output
- Pattern selected.
- Required states and tests.
- Accepted deviations.
- Pattern doc gaps.
- Review handoff to `review/references/implementation-pattern.md`.
