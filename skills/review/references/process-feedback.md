# Process Feedback Review

Use when reviewing actionable feedback on process, reviewer comments, repeated workflow friction, or process-learning events that may change skills, templates, agent definitions, quality automation, or implementation patterns.

## Checks
- Feedback is tied to observable evidence, not just preference.
- It is clear whether the fix belongs in project code/docs, a skill reference, a top-level router, an agent definition, a runtime adapter, quality automation, or process-learning backlog.
- The proposed process change is smaller than the failure it prevents.
- Repeated signals are separated from one-off judgment calls.
- Any skill update has an owner, acceptance criteria, rollback/deprecation path, and compatibility impact.
- The change does not create hidden gates or duplicate another router's authority.

## Output
- Feedback reviewed.
- Evidence quality.
- Likely owner.
- Recommended action.
- Accepted/rejected/deferred rationale.
- Skill/template/agent/doc updates needed.
- Validation needed before adoption.
