# Quality Automation

Use when choosing, reviewing, or revising deterministic checks for formatting, linting, typing, tests, builds, contracts, accessibility, security, dependencies, generated artifacts, docs, or CI/local preflight validation.

## Checks
- Commands are discoverable from repo docs/config.
- Checks match the work class and changed surfaces.
- Automation catches repeatable problems instead of relying on manual review.
- Checks are not excessively flaky, slow, noisy, or broad for the task.
- CI/local parity is understood.
- Any new quality tool has clear value, ownership, and approval.
